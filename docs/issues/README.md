## Что нужно знать в первую очередь

1. **Продукт всё ещё не работает end-to-end.** Алгоритм построения плана починен и покрыт тестами, но `TaskDependency` не наполняется **ничем**: единственный метод, который их создаёт, не вызывается ниоткуда. См. [001 §3.1](001-current-state.md#31-зависимости-задач-не-загружаются-никогда).
2. **Ядро не является провайдер-независимым.** Порты есть, но спроектированы вокруг GitLab и Яндекс.Трекера; ветвления по типу провайдера нет нигде — DI регистрирует ровно одну реализацию. См. [002 §2](002-provider-independence.md#2-фактическая-связанность-измерено).
3. **Ничего не проверено на живой системе.** Сборка чистая, 64 теста зелёные, но приложение не запускалось против реальных SQL Server, RabbitMQ, GitLab и Трекера. См. [001 §4](001-current-state.md#4-что-не-проверено).

## Как читать

Findings пронумерованы и содержат ссылку `файл:строка`. Утверждения о поведении помечены:

- **проверено** — воспроизведено запуском кода или тестом;
- **прочитано** — установлено чтением кода, но не запускалось;
- **не проверено** — гипотеза или внешний факт, который подтвердить не удалось.

Такое разделение важно: часть исходного аудита строилась на предположениях, которые при проверке не подтвердились.
